# Terrio Helsinki testing

This workspace uses [terrio](https://github.com/opengeos/terrio) 0.7.0 in a
local Python virtual environment. The examples use Helsinki's public WMS,
WMTS, WFS, and WCS services and need an internet connection.

## Run the examples

In PowerShell, from this workspace:

```powershell
.\.venv\Scripts\python.exe -c "import terrio; print(terrio.__version__)"
.\.venv\Scripts\python.exe .\helsinki.py
```

Run one service at a time with `wms`, `wmts`, `wfs`, or `wcs`, for example:

```powershell
.\.venv\Scripts\python.exe .\helsinki.py wmts
.\.venv\Scripts\python.exe -m unittest discover -s .\tests -v
```

The examples write to `output\` by default and replace the example files when
rerun. Use `--output-dir` to choose another folder. In VS Code, select
`.venv\Scripts\python.exe` with **Python: Select Interpreter** if the workspace
environment is not already selected.

To recreate the environment using this machine's Python 3.10 installation
(terrio requires Python 3.10 or newer):

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

The installed command-line tool can inspect the resulting files:

```powershell
.\.venv\Scripts\terrio.exe formats
.\.venv\Scripts\terrio.exe info .\output\wms_seutukartta.tif
```

## What the examples do

| Service | Example |
| --- | --- |
| WMS | Requests a 256 x 256 GeoTIFF of Helsinki's regional map and opens it with terrio. |
| WMTS | Requests one PNG tile, opens it with terrio, and writes a georeferenced GeoTIFF using the advertised tile matrix. |
| WFS | Lists layers and reads a small point layer using terrio's native WFS driver; requests two district features as GeoJSON and converts them to a GeoPackage with terrio. |
| WCS | Downloads a native 1 m DEM for a 1 km square downtown and creates a triangulated ASCII PLY mesh for QGIS. |

The outputs are `wms_seutukartta.tif`, `wmts_opaskartta.png`,
`wmts_opaskartta.tif`, and `wfs_kaupunginosat.gpkg`. The GeoTIFFs and
GeoPackage use EPSG:3879. The original WMTS PNG does not contain
georeferencing; the example derives it from the service's `ETRS-GK25` tile
matrix and preserves the image's color bands in the GeoTIFF.

Terrio 0.7.0 lists WFS as a native driver, but does not list WMS or WMTS
drivers. The map examples make ordinary HTTP requests and then use terrio to
read the returned images; they are not testing native WMS/WMTS drivers.
The WCS example likewise requests a GeoTIFF over HTTP and uses terrio to read
the DEM; triangulation and PLY export use NumPy and Python, not a terrio mesh API.

The WFS GeoJSON request is deliberately limited to two features. The native
WFS point-layer example disables paging and reads at most 250 features, so it
is also bounded. Change the constants in `helsinki.py` to experiment with
other layers or larger requests.

### WCS DEM to a QGIS terrain mesh

```powershell
.\.venv\Scripts\python.exe .\helsinki.py wcs
```

The coverage is `avoindata:Korkeusmalli_2021_1m` from
`https://kartta.hel.fi/ws/geoserver/avoindata/wcs`. The WCS 1.0 request uses
EPSG:3879, easting/northing BBOX order, and `resx=resy=1`; the returned CRS,
dimensions, bounds, and geotransform are checked before meshing.

The 1 x 1 km area around Kamppi and the Central Railway Station has these
EPSG:3879 bounds, in metres:

- Southwest: **25496200, 6672700**
- Northeast: **25497200, 6673700**

Outputs in `output\`:

- `wcs_korkeusmalli_2021_1m.tif`: the original 1000 x 1000 DEM subset.
- `wcs_korkeusmalli_2021_1m.ply`: an ASCII Stanford PLY triangulated mesh
  supported by QGIS's MDAL provider. At this location it has **1,000,000
  vertices** and **1,996,002 triangles**, with no decimation.
- `wcs_korkeusmalli_2021_1m.prj`: the source horizontal CRS definition.
- `helsinki_wcs_mesh_ply.qgz`: a ready-to-open QGIS project generated by the
  optional QGIS verification below, containing both the DEM and mesh with
  EPSG:3879 assigned explicitly.

Each DEM pixel center becomes an XYZ vertex. Adjacent samples form two
upward-facing triangles per grid cell; invalid/nodata samples leave holes
rather than creating spikes or being interpolated. The mesh spans 999 x
999 m between outer pixel centers, within the exact 1000 x 1000 m raster
footprint. PLY vertex properties use double precision; the ASCII values store
XY to millimetres and Z to six decimals. Triangle indices are zero-based.
Source elevations,
including negative ones, are retained without vertical exaggeration or datum
conversion. This is an open terrain surface, not a closed solid.

The PLY header includes `comment crs EPSG:3879` and the `.prj` sidecar
contains the source CRS. QGIS 4.2 did not automatically assign the CRS from
either, so when loading the `.ply` through **Data Source Manager > Mesh**,
explicitly assign **EPSG:3879** to the mesh layer. Alternatively, open
`output\helsinki_wcs_mesh_ply.qgz`, which assigns it for you. The mesh vertex
elevations appear as a scalar dataset. Use a 3D map view to view the surface
in perspective; loading the layer initially shows a 2D plan view.
Terrio 0.7.0 can also read the PLY vertices with `terrio.read_points`, but
reports no CRS for this file; retain EPSG:3879 separately.

The offline tests cover pixel-center coordinates, triangle winding, nodata
holes, PLY indexing, request parameters, and the full-resolution mesh counts.
To additionally check the actual outputs with an installed QGIS 4 runtime
and regenerate the project:

```powershell
& "C:\Program Files\QGIS 4.2.2\bin\python-qgis.bat" .\tests\verify_qgis_mesh.py
```

Adjust the QGIS installation path if needed. This verification does not
install QGIS bindings into the workspace environment; it uses QGIS's own
Python, loads the mesh through MDAL, checks its extent and counts, and
compares vertex elevations with the source DEM. If the earlier SMS project
exists, the script creates a separate PLY project from it, keeping the original
project and SMS mesh untouched. On subsequent runs it verifies an existing
PLY project without overwriting it.

### WFS-indexed WCS terrain tiles

This separate test fetches four official 500 x 500 m map sheets around
Helsinki Central Railway Station and writes one ASCII PLY mesh per sheet:

```powershell
.\.venv\Scripts\python.exe .\wcs_map_tiles.py
```

The bounded WFS GeoJSON request selects four `tunnus` values from
`avoindata:Karttalehtijako_05x05_km`. It reads each tile's polygon from WFS,
checks the EPSG:3879 geometry and 2 x 2 layout, and uses the polygon bounds to
request the corresponding 1 m DEM from WCS. The station is in `673496c`.

| `tunnus` | Location | EPSG:3879 bounds (min easting, min northing, max easting, max northing) |
| --- | --- | --- |
| `672496d` | Southwest | 25496500, 6672500, 25497000, 6673000 |
| `672497b` | Southeast | 25497000, 6672500, 25497500, 6673000 |
| `673496c` | Northwest | 25496500, 6673000, 25497000, 6673500 |
| `673497a` | Northeast | 25497000, 6673000, 25497500, 6673500 |

Outputs are in `output\wcs_map_tiles\`: each WFS `tunnus` is used unchanged
as the basename of a `.tif` DEM, `.ply` mesh, and `.prj` horizontal CRS
sidecar. `map_sheets.gpkg` contains the selected WFS polygons and mesh
counts/elevation ranges. Rerunning the test replaces these files; use
`--output-dir` to choose another folder.

Each tile is 500 x 500 DEM pixels. For the currently downloaded data, each
mesh has **250,000 vertices** and **498,002 triangles**, with no decimation.
Invalid/nodata samples leave holes, so counts can be smaller if the source
data changes. As in the single-area test, vertices lie at pixel centers.
The raster footprints touch, but the four separate meshes are **not stitched**:
there are no triangles between tiles, and neighboring edge vertices are
1 m apart across a sheet boundary.

QGIS 4.2 does not automatically assign the PLY's EPSG:3879 CRS. Assign it
explicitly when adding a PLY as a mesh, or create a separate project with
all four meshes, DEMs, and map-sheet outlines:

```powershell
& "C:\Program Files\QGIS 4.2.2\bin\python-qgis.bat" .\tests\verify_qgis_map_tiles.py
```

This uses QGIS's own Python, checks the mesh counts and sampled elevations,
and creates `output\wcs_map_tiles\helsinki_wcs_map_tiles.qgz` with the CRS
assigned. If that project already exists, the script verifies it without
overwriting it. For a custom output folder, pass the same `--output-dir` to
both commands. QGIS may color each mesh using its own elevation range; set a
common range on all four layers for consistent colors across tile boundaries.

### WFS compatibility notes

- The native driver rejected the `Kaupunginosajako` layer's GML geometry in
  our test. The example uses the service's GeoJSON response for that layer.
- With the native WFS point-layer example, terrio 0.7.0 returned EPSG:3879
  coordinates in northing/easting order; the same features in the service's
  GeoJSON response and the example rasters use easting/northing. Verify axis
  order before combining native WFS output with other datasets.
- Default WFS paging failed on the example point layer because the server
  could not sort without a primary key. The native example explicitly
  disables paging; the bounded GeoJSON request avoids it.
